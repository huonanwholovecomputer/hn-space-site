## 2026-10-17

- **目录、章节轴、「回到顶部」三处锚点跳转统一成本站自己的一套平滑滚动**，顺带修掉「点击后先瞬移到位、紧接着又微微移动一下」，以及「每点一次目录，浏览器历史就多一条」
  - 根因是同一次点击有**两套处理跑在同一条路上**：站点脚本在捕获阶段 `preventDefault` 之后自己即时跳转（落点偏移 92px），而主题的 footer 脚本又给每个 `a[href^="#"]` 单独挂了 `scrollIntoView({behavior:'smooth'})`（配合标题上的 `scroll-margin-top: 84px`），并顺手 `pushState` 一条历史记录。两套落点本来就差 8px（92 − 84）⇒ 先瞬移到位、紧接着平滑补上那 8px；代价是每点一次目录就多一条历史，用后退键回上一页要按很多次
  - 现在三处都改由 `window.__hnAnchorScrollTo` 接管，跳转走「固定时长 + 缓入缓出」，时长随距离在 400–900ms 之间（短跳不拖沓、长跳不「翻很久」）；目录链接与「回到顶部」另外在捕获阶段 `stopPropagation`，把主题那条监听器整条挡掉（历史记录也就不会再增加）
  - 以前不敢用平滑的真实担心是「动画期间页面高度变化会停偏」（旧注释写的就是这个）。实测 19045px 长文从顶部点中间章节：滚动全程里目标的绝对位置 **0px 漂移**——逐帧记录中「目标落点」一路恒为 8192。正文图都带 `width`/`height` 与 `--hn-wh`，空间在加载前就已经占住。所以真正要防的不是「高度会变」，而是**别把目标算死**：现在每帧重算落点，高度真变了也跟着走（且从当前值重瞄，不会跳）
  - 另一半是老底子问题：平滑滚动引擎把文档高度缓存在内部限位里，PJAX 刚换页时可能还是上一页的值 ⇒ 落点被夹短（历史「移动距离不对」的根源之一）。现在开始滚动前先刷新一次尺寸缓存
  - 「回到顶部」原来文章页走瞬移、其它页走主题的平滑（两套手感不一样），现在统一，并清掉地址栏里的 hash；首页右侧章节轴也交给同一套（此前它与目录各跳一次）
  - 开启「减少动态」，或当前页根本没有平滑滚动引擎时（搜索页、引擎初始化失败），退回瞬时跳转，落点仍然准确
  - 验收（无头 Chrome + CDP 逐帧取证）**24/24**：8192px 长跳单帧最大位移 151px、950ms 内收敛、方向反转 0 次、落点误差 0px、历史记录一条都没多；点最后一条目录（目标在文档末尾之外）被夹在真正能到的 18145px 处、不来回抖；PJAX 换页后立刻点目录误差仍为 0px；动画中途滚滚轮停在原地、不硬拽到目标；减少动态下没有引擎、瞬时到达且落点 0px 误差
    - 注：同一份代码在**软件渲染**的无头环境（`--disable-gpu`）里只有 20/24——那边的帧周期从约 6ms 变成 85–147ms，而单帧位移本来就正比于帧周期，按帧设的「够不够平滑」阈值因此会误判；功能类断言（落点误差、方向反转、历史记录、末尾夹取）在两种渲染下结论一致
- **惯性滑动还在跑的时候，键盘（PageUp / PageDown / Home / End / 上下键 / 空格）和右侧滚动条能立刻把滚动接过去**（10-16 反馈：惯性期间用这些方式滚动，界面在「惯性位置」和「新位置」之间来回闪现，最后还是被惯性拖走）
  - 根因：平滑滚动引擎（Lenis 1.3.11）**只接管滚轮**，键盘和滚动条完全不归它管；而它只在空闲时才承认「浏览器自己动了位置」。惯性期间它认为自己正在平滑滚动，于是浏览器把页面滚到哪、它下一帧就把自己的内部位置写回去——一帧一步互相盖（滚动事件里能直接看到 y 先到 0、紧接着又跳回惯性值）。上游同类问题（代码注释里记的是 lenis#107、lenis#168，未逐条复核）
  - 处置刻意不是「接管键盘」（那会跟输入框、焦点滚动、Home/End 的原生语义打架，还得自己算一屏多高），而是**谁动手就把惯性放下**：一按有滚动意图的键就停；另外用滚动位移检测兜住没有键盘事件的一切外来滚动（拖滚动条、Tab 把焦点滚进视野、页内查找、别的脚本 `scrollTo`）。之所以要两条路，是因为右侧滚动条属于浏览器的 UI、不在页面 DOM 里：拖它时页面收不到任何鼠标事件，只能靠位移检测发现
  - 三个 guard 缺一不可：只在「正在平滑滚动」时动手；页面滚动被锁住时（图片灯箱就是靠它锁背景）绝不动手，否则会把锁解开；位移差别要能区分「真有人在滚」与「引擎缓存的高度还是旧页面的」「浏览器回弹时 scrollY 越界」，否则正常滚动会被误杀。接管时留一个 `window.__hnScrollTakeover`（次数 + 原因）便于事后排查
  - 验收（逐帧时间线，非「有没有报错」）**35/35**：惯性中按 Home 停在顶部、之后 20 帧不再被拉回；按 PageDown 落点听浏览器的翻页（1259px，远过惯性原本想去的 600px），此后 20 帧里引擎内部值与真实位置的差恒为 0；纯滚轮惯性不受影响（单帧最大 16px、接管计数保持 0，说明没被误杀）；灯箱锁住滚动时按键不会把它解锁；被键盘打断后再滚滚轮，能从新位置平滑接着走；「进搜索页 → 回文章页」重建引擎后接管依然有效

## 2026-10-16

- **修复「打开图片后左侧的目录莫名其妙消失」**：在长文里滚到中后段点开一张图，左侧那条常驻目录（`position: sticky` 吸附栏）会整块不见。根因不在目录、也不在灯箱的显隐，而在灯箱打开时的**背景滚动锁写错了元素**：原先是 `document.body.style.overflow = 'hidden'`。overflow 有一条「传播」规则会把 body 的值作用到视口上，但浏览器**仍把 body 当成一个 overflow:hidden 的滚动容器** ⇒ 目录的「最近滚动口」变成了这个从头到尾不滚动的盒子，吸附偏移整体不再计入，目录退回文档流原位；而此时读者已经滚到 7586px 深处，目录实际停在视口上方约 7000px 处 ⇒ 观感就是「莫名其妙消失了」。现在锁改到 `<html>`（`documentElement`）上：视口照样不可滚（滚轮 / PageDown / Home / 滚动条全拦住，滚动位置一位不动），sticky 照常吸附
  - 实测（无头 Chrome + CDP，真实鼠标点图）：修复前目录 `y` **84 → −7057**（可见 true → false）；修复后 **84 → 84**，滚动位置 7586 不变。另外做了 7 组锁法隔离实验：只有「锁 body」会坏 sticky；「锁 html」与「html+body 都 overflow:clip」都不坏，但 clip 连程序化滚动都一起禁掉（Lenis 的 `window.scrollTo` 会失效），所以没采用
  - 锁由灯箱自己独立提供、不再依赖 Lenis 的 `.lenis-stopped` 类，因此「减少动态」（根本没有 Lenis）、搜索页、Lenis 初始化失败等情况下一样有效（关闭时按打开前的状态原样归还，不擅自启动本来就停着的 Lenis）
  - 回归覆盖：1280 / 1920 两档视口 × 普通动效 /「减少动态」无 Lenis，加「PJAX 换页进文章后开图」与「关于页竞赛证书画廊」，共 55 条断言全过；其中专门留了一条**回归哨兵**断言——body 的内联 overflow 必须为空，防止以后有人再把这把锁写回 body
- **图片灯箱改成「从原图长出来、再缩回原图」的空间延续动效**：以前点开一张图是「图片原地淡入 + 轻轻弹一下」，可它打开的东西明明来自页面上一个具体的位置。现在从你点的那张原图的**位置与大小**平滑放大到居中大图（380ms），关闭时沿同一条路缩回去（280ms，**退场比入场快**），进出共用一条 `cubic-bezier(0.23, 1, 0.32, 1)` 保证路径可逆；遮罩改为**渐显**（240ms 内从透明压到 `rgba(0,0,0,0.85)`）；放大／缩小／关闭这几个控件比大图晚 100~160ms 错峰淡入并上浮 10px
  - 做法是 FLIP：点击时记下那张原图的视觉矩形，与大图 1:1 时的布局盒一起算出 `translate(dx,dy) scale(s)`，用 WAAPI（`Element.animate`）播——几何量运行时才知道，而且必须可中断：CSS 动画只能从零重放，长动画播到一半关闭会看到跳变。**退场起点取"当前画面值"**（`getComputedStyle` 会把还没播完的入场动画一并算进去），所以"刚打开就关"不会跳回去（实测单帧位移 7px）
  - 三条容易踩的细节：① 大图的尺寸要用 `offsetWidth/Height`（布局尺寸，不含 transform），中心由 `getBoundingClientRect()` **减掉当前内联位移**反推——那个 rect 含 transform、也含正在播放的动画；② 用户一滚轮／拖拽，入场动画立刻 `cancel()` 让位，绝不和手动缩放抢同一个 `transform`（实测滚轮打断后视觉缩放真实生效 1.149）；③ 控件入场用的是独立的 `translate` 属性而**不是** `transform`——这些控件身上已经写着 `translateX(-50%)`／`translateY(-50%)` 做居中，用 transform 做入场会把居中弄丢
  - 「减少动态」下整条不做，只保留遮罩淡入淡出与图片淡入（opacity 类变化保留、运动类去掉）；拿不到原图矩形（图片还没解码等）时退回原来的原地弹入，绝不"啪"地出现

- **修复一个很隐蔽的滚动故障：访问过搜索页之后，鼠标滚轮会卡死在顶部**（触控滑动仍正常，所以第一眼像"鼠标坏了"）。原因是平滑滚动引擎的内部状态被写坏，且**它的实例会在整个会话里跨页面复用**，于是一次抖动被带到了之后每一页；滚轮归它接管、触控不归它管，这才出现"能滑/不能滑"的分裂现象。修复分两层：搜索页**不再持有**滚动引擎（离开时重建全新实例，切断跨页传播）；另外给它加了看门人——一旦发现内部状态被写坏，立即退回浏览器原生滚动并掐断它的滚轮接管，宁可少一层缓动也不让页面卡住
- **上面那个滚动故障，这轮找到了真正的根因并根除**：站内搜索包（Fuse）与平滑滚动引擎（Lenis）都把内部使用的单字母变量（`e`、`t`）声明在了**全局**上，于是互相覆盖。无刷新进入搜索页时，搜索包把 `e` 覆盖成了一个普通对象，滚动引擎此后再也无法被创建（内部报 `e is not a constructor`），而这段失败又被代码静默吞掉——结果是平滑滚动消失，控制台却一个字都不说。修复方式：给这两个第三方包各自套一层函数作用域，内部名字不再落到全局（滚动引擎对外只暴露 `Lenis`）；同时让「引擎创建失败」必须在控制台报错并记录原因，这类问题不会再无声无息地溜过去。此前记录过的「滚轮卡死在顶部」「内部滚动值被写成非数字」其实是同一个撞名（`t` 被换成了搜索包的工厂函数），这次一并根除
